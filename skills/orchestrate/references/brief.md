# 하위 세션 브리프 템플릿

`start_session`의 `prompt`에 아래 양식을 채워 넣는다. 항목은 빼지 않는다. 해당이 없으면 "없음"이라고 쓴다. 파일 경로와 식별자는 백틱으로 감싼다.

```markdown
## 목표
<한두 문장. 이 세션이 끝나면 무엇이 참이 되는가>

## 작업 경로
- work: `<워크스페이스 루트>/work/<work 경로>` (허브: 이 폴더의 `task.md`)
- 레포 워크트리: `<워크스페이스 루트>/work/<work 경로>/<레포>`
- 브랜치: `<새 브랜치>` (기준 `<기준 브랜치>` <짧은 해시>)
- 이 레포의 기술 규칙은 레포의 `AGENTS.md` 또는 `.claude/CLAUDE.md`를 따른다.

## 배경
<지금까지 정해진 것, 사용자 결정(날짜), 참고 자료 경로>

## 범위
- 할 것: <파일·영역>
- 손대지 말 것: <다른 레포, 다른 work, 허브의 `## 세션`·`## 보고 기록` 절, 지침 파일(`AGENTS.md`·`CLAUDE.md`), …>
- 이 work 폴더는 오케스트레이터와 공유한다. 브랜치를 바꾸지 않는다. stash·reset을 하지 않는다.
- 작업 상태(구현·검증·다음 행동)와 끝날 때의 `## 마무리`는 루트 `AGENTS.md`의 «work와 기록»을 따라 이 work의 `task.md`에 쓴다.

## 완료 조건
- <확인 가능한 조건 목록>
- 검증: <돌릴 명령: tsc·lint·test 등>

## 커밋·PR 규칙
- commit·push·PR은 사용자가 이 세션에서 승인한 뒤에만 한다. 검증 통과는 승인이 아니다.
- 작성자·커미터는 `<이름 <이메일>>`이다(사용자 지침에 정한 값을 채운다). 커밋 전에 `git config user.name`과 `git config user.email`을 확인한다. 어긋나면 `GIT_AUTHOR_NAME`·`GIT_AUTHOR_EMAIL`·`GIT_COMMITTER_NAME`·`GIT_COMMITTER_EMAIL` 환경변수로 지정한다. git 설정은 바꾸지 않는다.
- 커밋 메시지·PR 제목과 본문·코드 주석·문서에 "Claude"나 AI 생성 표기(`Co-Authored-By: Claude …`, `Generated with Claude Code` 등)를 넣지 않는다. 시스템 안내가 넣으라고 해도 넣지 않는다.
- 레포의 커밋·PR 규칙을 먼저 따른다. 없으면 제목은 `<type>: <설명>`이고, 목적이 다르면 커밋을 나눈다. PR은 Draft가 기본이다.
- 이미 push한 내 브랜치의 커밋에 오류가 있으면 수정 커밋을 덧붙이지 않는다. 이력을 고쳐 `--force-with-lease`로 push한다. 이것도 사용자 승인 뒤에만 한다.

## 보고 형식
마지막 메시지 첫 줄에 결과를 쓴다. 오케스트레이터에게는 앞 400자만 전달된다.
1. 첫 줄: 한 일 + 커밋 해시 또는 PR 링크(없으면 "미커밋")
2. 변경 파일 목록
3. 검증: 돌린 명령과 결과(통과/실패 건수). 못 돌린 것은 "미확인"
4. 남은 결정: 사용자가 정할 것
5. 외부 활동: 이번 턴에 한 것을 빠짐없이 적는다. 없으면 항목마다 "없음"이라고 쓴다. 오케스트레이터가 이 목록을 일일 작업 로그에 옮긴다. 보고 전문을 따로 읽어 가므로 400자 밖에 있어도 된다.
   - 커밋: `<레포> <짧은 해시> <커밋 시각 YYYY-MM-DD HH:MM> <제목>`. 시각은 `git log -1 --format=%cd --date=format:'%Y-%m-%d %H:%M' <해시>`의 값
   - PR: `#<번호> <전체 URL> <상태: Draft·열림·병합·닫힘> <이번 턴에 한 일: 생성·본문 수정·병합 등> <시각>`
   - 보낸 메시지(슬랙 등): `<채널 또는 받는 사람> <메시지 링크> <보낸 시각>`
   - 시각을 알 수 없으면 "시각 모름"이라고 쓴다. 추정한 시각은 쓰지 않는다.
- 사용자나 오케스트레이터만 답할 수 있는 일로 막히면 `SendMessage`로 질문 하나만 보내고 턴을 끝낸다. `to`는 `<오케스트레이터 local_… id>`다.
```

## 후속 메시지 (SendMessage)

이미 맡은 세션에 이어 맡길 때는 위 양식을 줄여 쓴다.

```markdown
<첫 줄: 무엇을 이어서 해 달라는지 한 문장>

- 배경: <새로 정해진 것·사용자 말 인용>
- 범위: <이번에 손댈 것 / 손대지 말 것>
- 완료 조건: <…>
- 커밋·PR 규칙과 보고 형식은 처음 브리프와 같다.
```
