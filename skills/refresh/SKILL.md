# 기록하고 비우고 다시 읽기

대화 맥락은 버리고, 이어가는 데 필요한 것만 디스크에 남긴다.

- 대화가 있는 세션에서 `/refresh` → 1절(기록하고 비우기)
- 비운 뒤 새 대화 → 2절(다시 읽기). 사용자가 `/refresh`를 다시 치지 않아도 된다. agent-harness 플러그인의 SessionStart 훅(`hooks/session-start.sh`)이 기록 파일에 `## 이어받기 메모`가 남아 있으면 그 메모를 시작 맥락에 넣고, 첫 메시지가 무엇이든 2절부터 하라고 알린다. 빈 대화에서 `/refresh`를 쳐도 2절이다.

`/refresh` 앞에 이전 대화가 있으면 1절, 없으면 2절이다.

## 기록 파일

| 이 세션 | 기록 파일 |
|---|---|
| 묶음 전담 오케스트레이터 (cwd가 묶음 폴더) | 그 묶음 `task.md` |
| 루트 오케스트레이터 (cwd가 워크스페이스 루트) | `work/orchestrator.md` |
| work를 맡은 세션 (cwd가 work 폴더) | 그 work `task.md` |

- 어디에도 해당하지 않으면 기록할 곳이 없다고 알리고 멈춘다. 그냥 `/clear`를 쓰거나 work부터 만들라고 안내한다.
- 루트 세션이 `work/orchestrator.md`의 `오케스트레이터:` 줄의 세션이 아니면 해당하지 않는다.
- 다른 세션도 쓰는 파일이므로 바꿀 줄만 고친다(Edit).

## 1. 기록하고 비우기

1. 빠진 기록을 채운다. 대화에만 있고 파일에 없는 것을 찾아 제자리에 적는다.
   - 사용자가 정한 것: `## 결정 사항`에 날짜와 함께
   - 아직 답을 기다리는 질문, 결과를 기다리는 세션: `## 진행 중`(오케스트레이터) 또는 `## 다음 행동`(work 세션). 질문은 원문으로
   - 진행 상황: 오케스트레이터는 `## 세션` 명단 상태와 `## 보고 기록`, work 세션은 구현·검증 절
   - 오케스트레이터는 오늘 작업 로그(`log/<날짜>.md`)에 빠진 사건도 덧붙인다(orchestrate 스킬 7절)
   - 여러 work에 두루 맞는 사용자 선호는 기록 파일이 아니라 메모리에 둔다
2. 기록 파일 맨 아래에 `## 이어받기 메모`를 쓴다. 이미 있으면 내용을 바꾼다.

   ```markdown
   ## 이어받기 메모

   - 2026-11-05 16:40 <세션 이름 또는 역할>이 `/refresh`로 대화를 비움
   - 지금 하던 일: <한 줄>
   - 다음 첫 행동: <한 줄>
   - 대화에서만 알던 것: <파일 어디에도 없는 맥락. 없으면 "없음">
   - 다시 읽을 것: <이 파일 외에 먼저 볼 파일·명령>
   ```

3. 사용자에게 기록한 것을 다섯 줄 안으로 보여 준다. 무엇을 어느 절에 적었는지만 쓴다.
4. `mcp__ccd_session_mgmt__clear_session`을 `session_id: "self"`로 부른다. 앱이 승인을 묻는다. 대화는 이 턴이 끝나고 세션이 쉴 때 비워진다.
5. 마지막 메시지로 "비워지면 아무 메시지나 보내면 기록을 읽고 이어갑니다"라고 쓰고 턴을 끝낸다.

- 비우기 전에 사용자가 다른 메시지를 보내면 비우기가 취소된다. 그때는 기록만 남은 상태이니 그대로 이어서 일한다.
- 옛 대화는 앱의 "Resume previous session"으로 되돌릴 수 있다.

## 2. 다시 읽기

1. 위 표로 기록 파일을 정하고 연다. `## 이어받기 메모`가 없으면 "이어받을 메모가 없다"고 알리고 멈춘다.
   - 시작 맥락에 함께 들어온 claude-mem 내용(Work state 목록, recent context 관찰 기록)은 이어받기에 쓰지 않는다. 낡았거나 다른 세션 것이 섞여 있다. 정본은 기록 파일이다.
2. 메모의 "다시 읽을 것"을 읽는다. 오케스트레이터는 orchestrate 스킬 파일(이 파일 기준 `../orchestrate/SKILL.md`)을 읽고 8절 "이어받기" 순서대로 맞춰 본다. work 세션은 그 work `task.md` 전체와 워크트리의 `git status --short`·`git log --oneline -5`를 본다.
3. 기록과 실제 상태가 다르면 행동하기 전에 사용자에게 먼저 알린다.
4. `## 이어받기 메모` 절을 지운다. 메모의 내용 중 아직 유효한 것은 이미 제자리(진행 중·다음 행동)에 있어야 한다. 없으면 옮기고 지운다.
5. 오케스트레이터는 작업 로그에 `[세션]` 줄을 남긴다: `- HH:MM [세션] - — /refresh로 대화 비우고 이어받음`.
6. 사용자에게 이어받은 내용을 다섯 줄 안으로 알린다: 하던 일, 기다리는 것, 다음 첫 행동. 다음 행동은 사용자가 말하기 전까지 시작하지 않는다.
